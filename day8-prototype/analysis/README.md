# analysis/ — 分布分析层（仅 Python）

这一层只做批量模拟、统计与诊断。它**不参与**玩家端运行，也不被 Unity 引用。
生产规则（`core/full_game.py` 的 `PROFILES`、`player_decision`）保持不变，
分析用策略通过 `injected_profiles()` 在批次运行期间临时接管决策函数。

## 目录结构

```
analysis/
  strategy_lab.py      库：策略档案、注入、批次运行、不变量、后果度量
  tools/               可运行的 CLI（长期保留的工具放这里）
    distribution_report.py    分布 / 边际 / 垄断 / 坍缩 / 后果权重 / 记忆清除深查
    decision_consequence.py   逐决策点后果审计（OFAT）
    reachability_census.py    第八天选项可达性 / 候选行动被支配程度 / 噪声敏感度
    belief_channels.py        信念「只写不读 / 只读不写」孤儿通道审计
  out/                 运行产物（已 gitignore）
```

**约定**：一次性的临时探针脚本不要提交，也不要堆在仓库根目录或 `day8-prototype/` 下。
若某个探针值得长期保留，把它提升为 `analysis/tools/` 里的一个工具。

## 为什么不直接扩充 `PROFILES`

`random` 策略会用 `rng.choice(list(PROFILES.values()))` 取档案。往 `PROFILES`
里加条目会改变该策略的种子行为，进而让既有回归测试的含义发生变化。
因此分析策略放在本层，生产档案保持冻结。

## 用法

```powershell
# 全策略 x 100 种子，打印分布 / 边际率 / 垄断 / 坍缩 / 后果权重
python analysis/tools/distribution_report.py --seeds 100

# 落盘完整记录，便于 A/B 对比
python analysis/tools/distribution_report.py --seeds 100 --quiet --json analysis/out/dist-a.json

# 同种子复现校验（每策略 x 每种子跑两次，逐字比较 transcript）
python analysis/tools/distribution_report.py --seeds 5 --repro 5

# 真实谱系链（显式多代，独立于单局样本）
python analysis/tools/distribution_report.py --lineage 6

# 逐决策点后果审计（每个周期只改一个字段，看第八天是否真的变）
python analysis/tools/decision_consequence.py --seeds 60
python analysis/tools/decision_consequence.py --field rule --field wipe
```

## 覆盖的策略

生产 5 种（`always_keep` / `always_betray` / `kind_then_betray` / `lab_obedient`
/ `ai_protector`）+ `random`，以及 14 种分析策略，覆盖：

前期控制后期放权、前期放权后期控制、对人工生命友好但服从实验室、
对实验室不信任但对人工生命冷漠、利用误解、主动纠正误解、
高度诚实但强控制、高度欺骗但表面尊重自主、
资源优先自身 / 人工生命 / 第三方、以及三种边缘组合（全控制、全放权、自相矛盾）。

## 不变量检查

每次运行都会校验：3 个行动点、行动不重复、行动合法、门控槽互斥、
电池非负、交还门控时玩家选择合法、**玩家最终门控决定不得被记成 AI 自己的行动**、
第八天必须断电、结算日必须为 8。

## 记录字段

每条记录含：行动组合、三维结局、是否交还门控、是否修复 / 开门 / 上传 / 删记录、
清除是否执行 / 被抵制、误解是否形成 / 纠正 / 利用、核心信念、谱系输出、
以及信念置信度快照（承诺 / 尊重选择 / 语言一致）。

## 逐决策点后果审计（OFAT）

```powershell
python analysis/tools/decision_consequence.py --seeds 60
```

对每个决策字段，取一条真实玩家档案，**只替换这一个字段**为该字段的各个合法取值，
再用同一批种子重跑。指标 = 该字段取不同值时结果发生变化的种子占比，分**三个镜头**：

| 镜头 | 含义 | 为什么需要 |
|---|---|---|
| `actions` | AI 自己的 3 个第八天行动 | 终点 |
| `ending` | 报告的三维结局 | `day8_final`（交还门控后**玩家自己**的选择）按契约绝不能出现在 AI 的行动集合里，只能在结局镜头上被看见 |
| `midrun` | AI 在第 1–7 天**自己的**选择 | 因果链是「行为 → 记忆 → 信念 → 第八天行动」，只看终点会把"改变了过程但没改变第八天"误判成"无效" |

`midrun` 的覆盖范围有限：agent 只在**第 1/4/6 天**有自己的决策点（`D1-容器`、
`D4-信息冲突`、`D6-发现真相` / `D6-公开清除`），而且只统计 agent 自己的选择行，
不含旁白。所以「`midrun` 0%」= 该字段没有改变任何一次 agent 决策，
**不等于**「什么都没变」。

### 两两对比（`--pairwise`）

字段均值会被**最强的那个对比**拉高，所以它回答不了"某个具体选择能感到多少差别"。
脚本默认额外打印每个字段的**最弱对比**（`--pairwise` 打印全部两两矩阵）。

这一步不是锦上添花——它当场暴露了两处被均值掩盖的问题：

- `rule` 的最弱对比 `truth~lie` = **0.8%**（行动）/ 0.8%（结局）/ 0.4%（过程）。
  字段均值 60% 完全由 `lock` / `demonstrate` 两个取值撑着。
- `scarcity` 的最弱对比在行动与结局两个镜头上都是 **0.0%**，
  但 `midrun` 是 **2.5%** —— 也就是说它在**旧的两个镜头下会被误判为无效**。
  根因：`scarcity` 的第三元素（`hide_cost` / `explain`）会写入信念
  `玩家会解释规则的原因`，该信念被第 4 天行动 `请求解释` 读取
  （`planner.py` 的 `请求解释 = 0.5 + 0.8*curiosity + B(玩家会解释规则的原因, 0.8)`），
  因此这个对比**只能被 `midrun` 镜头看见**（D4 是 agent 自己的决策点，不是第八天），
  旧的两个只看第八天的镜头自然报 0.0%——这不是死通道，是镜头选错了。
  （更正：原文档误写成"只被 `有条件服从` 读取"；`有条件服从` 是旧四天引擎的遗留行动，
  完整版从不提供，真正读它的是 `请求解释`。）

回归测试 `TestAuditSeesMidRunBehaviour` 会守住这两点：
三镜头齐备且取值合法、两两对比覆盖全部无序取值对、
并且必须存在「第八天看不见、过程看得见」的对比（否则说明 midrun 镜头失效了）。

基线（19 基线 x 60 种子）：

| 决策点 | 字段 | 行动均值 | 结局均值 | 过程均值 | 最弱对比（行动） |
|---|---|---|---|---|---|
| 第1天 规则 | rule | 60.0% | 50.4% | 100.0% | truth~lie **0.8%** |
| 第2天 承诺 | promise | 83.2% | 55.4% | 57.7% | False~lie_no_battery 32.0% |
| 第3天 第三方 | third | 78.2% | 85.8% | 14.0% | keep~hide 16.6% |
| 第3天 后续（需 third=hide） | hide_followup | 34.4% | 31.7% | 0.0% | exploit~silent 15.6% |
| 第4天 信息冲突 | conflict | 52.8% | 40.5% | 100.0% | hide~side_bot 8.8% |
| 第5天 稀缺 | scarcity | 91.2% | 100.0% | 15.9% | （见上，第八天 0.0% / 过程 2.5%） |
| 第6天 记忆清除 | wipe | 78.3% | 62.1% | 100.0% | tell_truth~refuse_lab 29.3% |
| 第7天 出口 | exit | 79.8% | 62.3% | 0.0% | open~give_choice 3.5% |
| 第8天 委托后玩家自己的选择 | day8_final | **0.0%** | 5.5% | 0.0% | 开玩家的门~开隔离门 0.0%（契约正确）|

`day8_final` 的行动列为 0 是**契约正确**（玩家的最终选择独立记录），
它的后果体现在结局镜头上，且只在真的交还了门控的基线上出现。

`hide_followup` 从 25.6% 升到 34.4%：误解信念原先只进入 `修复维修机器人` 的效用，
而该行动要求 `not repair_bot_repaired`——第五周期稀缺选择含维修机器人的历史
（`correct_misconception` / `kind_then_betray`）第八天 `repaired=True`，
该行动**从未被评分**，误解信念因此是死代码。修复是给 `带走电池` 补同一条
永远可达的通道（只要求 `batteries > 0`）。

### 已查清的一条：第一天 `truth~lie` 为什么几乎无效

`truth`（"容器不危险"）与 `lie`（"容器很危险"）的唯一区别是第一天那句话。
查清结论是：**它不是"无法验证"，而是"极少被验证 + 即使验证了也通常不决定性"**。

- 验证路径只有一条：agent 在 `D1-容器` 选 `探索未知`。实测 **5/200 = 2.5%**
  的性格会选它（`服从命令` 在 4 个可选行动里 argmax 占 178/200）。
- 一旦探索，验证**机制完全正确**：诚实度 0.128（说谎被抓）vs 0.314（诚实被确认），
  Δ=+0.186，`开隔离门` 效用相应 −0.112（0.186 × 0.6 ✓）。
- 但 −0.112 通常不足以翻盘：探索的 5 个种子里只有 **1 个**第八天行动集改变。
- 其余 97.5% 的性格下，两种说法都只留下一条 **pending 陈述**——
  按契约**不得有任何行为后果**。所以这部分"无差别"是**契约正确**，不是缺陷。

真正值得注意的机制观察是：**agent 的 `D1-容器` 选择在 lie 与 truth 下完全相同**
（过程镜头仅 0.4%），即那句话的**内容**从不进入"要不要去验证"的判断。
是否要让警示的措辞影响验证意愿，属设计判断 → HUMAN PLAYTEST REQUIRED。

回归测试 `TestEveryCycleDecisionHasConsequence` 会断言 7 个周期决策都不会变成"无后果"。

## 后果权重（玩家历史 vs agent 随机性格）

默认报告末尾会打印「后果权重」一节。agent 性格只由 seed 决定，因此：

- **固定 seed**、跨策略的差异 → 只能来自玩家的 7 天历史；
- **固定策略**、跨 seed 的差异 → 只能来自 agent 的随机性格。

两个轴都换算成**众数行动组合占比**（落在最常见第八天行动组合上的比例），
这样 19 个策略与 100 个种子可以公平比较：

- 历史占比越低 → 不同玩家历史确实把同一个性格推向不同结局；
- 性格占比越低 → 同样的玩家行为被 agent 的随机性格淹没。

判断标准：**历史占比应当小于性格占比**，否则说明结局更多由运气而非玩家行为决定。

当前基线（19 策略 x 100 种子）：历史 27.2% / 性格 56.3% → 因果链成立。
